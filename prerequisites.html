Prerequisites

Confirm these are in place before you begin.

Org and licensing

Three capabilities have to be licensed in the org for this feature to work end to end — the Data Cloud data kit (Step 1), the Scoring Framework model (Step 2), and the Copy Field Enrichment writeback (Step 3). Here's what each one needs.

Needed forLicense / entitlementNotes
Foundation (all steps) Health Cloud Enterprise, Performance, or Unlimited edition, in Lightning Experience.
Data kit — Step 1 Data Cloud (Data 360) A separate entitlement from Health Cloud — it is not included with a Health Cloud license. Provides the data model objects (DMOs), data streams, and data kits. You also need at least one active data space, which you select in Steps 1 and 2.
Scoring Framework — Step 2 Einstein Studio (Model Builder) on Data Cloud + the Scoring Framework entitlement The template trains its predictive model as a Data Cloud Einstein Studio model, so it needs Data Cloud's AI (Einstein) capability enabled. The Scoring Framework entitlement — a permission-set license that lets you install Scoring Framework template configurations — can appear under a name such as Scoring Framework or AI Accelerator depending on your release.
Writeback — Step 3 Data Cloud (Data 360) + the Health Cloud Platform permission-set license Copy Field Enrichment is a standard Data Cloud feature — no extra SKU. The Health Cloud Platform permission-set license (HealthCloudPlatformPsl) must be assigned to the Data Cloud integration user so the writeback can update the Health Cloud record. See Step 3.

You also need Clinical Service Request records in your CRM for the model to train on — see Data readiness, below.

Confirm the exact entitlement names with your account team Data Cloud (Data 360) and the Scoring Framework / Einstein entitlements are licensed separately from Health Cloud, and their customer-facing names can vary by release. This template is relatively new, so if a step is blocked by a missing license, confirm the current entitlement names and provisioning with your Salesforce account team.

Data readiness

The scoring template runs readiness checks when you install it. Meet these so the checks pass:

RequirementDetail
The ClinicalServiceRequest DMO is mapped The readiness check requires Id, ClinicalServiceRequestPriority, and ClinicalServiceRequestStartDate to be present.
At least 400 Clinical Service Request records Fewer than 400 records fails the readiness check.
A mix of accepted and not-accepted requests The model predicts acceptance and needs both outcomes to train. If all requests have the same outcome, training can produce a single-class model. This check warns but does not block install.
What "accepted" means A request counts as accepted when IsAccepted is true, or when the request Status is Active or Completed. This is how the default training label is defined.
