Prerequisites

Confirm these are in place before you begin. Most setup failures trace back to a missing item here.

Org and licensing

  • Health Cloud enabled (Enterprise, Performance, or Unlimited edition, Lightning Experience).
  • Data Cloud provisioned, with at least one active data space. You'll select this data space in Steps 1 and 2.
  • Referral Management set up, so that Clinical Service Request records exist in your CRM.

Data readiness

The scoring template runs readiness checks at install time. Make sure your CSR data meets them, or the install will warn (and training can fail):

RequirementWhy
The ClinicalServiceRequest DMO is mapped and populated The model reads from the CSR DMO. The readiness check requires Id, ClinicalServiceRequestPriority, and ClinicalServiceRequestStartDate to be present.
At least 400 Clinical Service Request records The model needs enough rows to train. Fewer than 400 rows fails the readiness requirement.
A mix of accepted and not-accepted requests The model learns to predict acceptance, so it needs both outcomes. If every request has the same outcome, training produces a single-class model. The install surfaces a warning but does not block.
What "accepted" means A request counts as accepted when IsAccepted is true, or when the request Status is Active or Completed. This is how the default training label is defined — see the Target Variable parameter.

Permissions

You — the admin running the setup — need:

TaskPermission
Access Data Cloud Setup and deploy data kitsSystem Administrator profile, or the Data Cloud Architect permission set
Install and manage Scoring Framework templatesCustomize Application + Modify All Data + Scoring Framework Admin

A separate set of permissions is needed by the integration user that performs the score writeback. Those are covered in Step 3 — they are the most commonly missed part of the whole setup.

Quickest path to a clean install Run the setup as a System Administrator who also holds the Health Cloud Platform permission set license. This avoids both the Scoring Framework permission gaps and the writeback-user gap described in Step 3.
