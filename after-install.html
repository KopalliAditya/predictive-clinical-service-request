After You Install — What to Check and Where

Once the template install finishes, confirm each piece of the pipeline it built. Check them in order — each one feeds the next.

The setup creates its pieces in two places: Data Cloud (now called Data 360) holds the data transforms, the AI model, and the scoring data; your CRM holds the final Referral Score. Work through the checks below top to bottom. If a check fails, fix it before moving on — a later piece can't be right if the one before it isn't.

What are these things? This page says where to check each piece and what good looks like. For a plain-language explanation of what the two data transforms and the AI model actually do, see How It Works.

1. CSR data landed in the DMOs

Before anything can run, your Clinical Service Request data has to be in Data Cloud. The data kit (Step 1) maps it into data model objects (DMOs) — the standardized tables everything downstream reads.

Where to check

In the Data Cloud (Data 360) app, open the Data Explorer tab. Pick your data space, then select the Clinical Service Request data model object and browse its records.

Looks right when: the DMO returns rows — at least the 400 records the model needs to train. An empty DMO means the data streams haven't run or finished; go back to Step 1.

Docs: Data Explorer · Permissions for Data Explorer

2. The two Batch Data Transforms

A Batch Data Transform (BDT) is a Data Cloud job that reads one or more DMOs, derives and reshapes fields, and writes the result to another DMO on a schedule. The scoring template builds two of them, and you can see both here.

Where to check

In the Data Cloud (Data 360) app, open the Data Transforms tab. Both transforms the template created appear in the list with type Batch. Open each one to see its definition and run history.

Training transform

Reads your resolved Clinical Service Requests, computes the model's features and the accept/not-accept label, and writes the result to the ClinicalServiceRequestTrainingData DMO. This is the labeled history the model learns from.

Scoring transform

Reads the Clinical Service Requests you want scored, computes the same features, calls the model to predict each one, and writes the result — including the predicted score — to the ClinicalServiceRequestScoringData DMO.

Looks right when: both transforms show a Success last-run status (not failed or never-run). If a transform hasn't run yet, you can run it manually from this tab. The custom filters you set in Step 2 decide which requests each one reads; for a look at what each transform does internally, see How It Works.

Docs: Batch Data Transforms overview · Check the status of a data transform · Run a data transform

3. The AI model

The template trains a predictive model in Einstein Studio (Data Cloud's model-building tool, shown as Model Builder). It's a binary classification model that learns, from the training dataset, how a request's features relate to whether it was accepted, and outputs a Derived Score (0–100) for each scored request.

Where to check

In the Data Cloud (Data 360) app, open Model Builder (listed under the AI / models area of the app). Open the model the template created to see its status, versions, and scoring metrics.

Looks right when: the model's status is Active. A model that stays in Activating usually means the training label came out all one value (every request accepted, or none) — see Troubleshooting.

No public help URL for Model Builder Einstein Studio / Model Builder is reached through the Data Cloud app rather than a stable public help article. Use the in-app path above. For the underlying DMOs the model reads and writes, use Data Explorer.

4. App Hub — the app the template generated

Installing the template provisions an app that holds the assets it created (the data transforms, the model definition, and related metadata). App Hub is the Setup page that lists these template-generated apps and their install status.

Where to check

In Setup, go to Intelligent Apps → App Hub (/lightning/setup/AppHub/home). Find the app the template created. Its App Install History shows whether the install completed or failed, and when.

Looks right when: the app shows an installed / completed status with no install errors. If the install failed, App Install History is where the error surfaces — and it's why the Enable Asset Saving option in Step 2 exists (turn it on to keep a failed install's partial assets for inspection).

Reached from Setup, not a help URL App Hub is a Setup page rather than a standalone public help article. Use the Setup path above (Intelligent Apps → App Hub).

5. Scores in the scoring DMO

Once the model is Active and the scoring transform has run, the predicted score is stored in Data Cloud — not yet in your CRM.

Where to check

Back in Data Explorer, open the ClinicalServiceRequestScoringData DMO and confirm the DerivedScore_prediction__c field has values.

Looks right when: scored rows carry a numeric DerivedScore_prediction__c (0–100). If this field is empty, the model hasn't scored yet — recheck that the model is Active (step 3) and the scoring transform ran (step 2).

Docs: Data Explorer

6. Referral Score on the Clinical Service Request

The last hop copies the score out of Data Cloud and onto the CRM record, using Copy Field Enrichment (Step 3). This is the value referral coordinators actually see.

Where to check

Confirm the enrichment first: in the Data Cloud (Data 360) app, in the area for acting on data, open the Copy Field Enrichment the template created and confirm its last run succeeded. Then open a scored Clinical Service Request in the CRM and look at the Referral Score field.

Looks right when: the Referral Score on the CSR matches the DerivedScore_prediction__c in the scoring DMO. If the DMO has a score but the CSR doesn't, the writeback is the problem — recheck the integration user's permissions in Step 3.

Docs: Act on data in Data 360 (the area that includes Copy Field Enrichment)
