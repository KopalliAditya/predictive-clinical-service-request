Step 2 — Install the Predictive Analytics for Clinical Service Requests Template

Install the scoring template and set its parameters in the Scoring Framework.

Open the Scoring Framework and install the template

1

From Setup, go to Scoring Framework.

2

Find and install the Predictive Analytics for Clinical Service Requests template.

3

Step through the install wizard and set the parameters below. Each parameter has a default value.

Data Space

Data Space
Optional  ·  Default: default

The Data Cloud data space the model reads from and writes to. Set it to the same data space you deployed the data kit into in Step 1.

Features

Each feature is a toggle that tells the model it may use that signal. Priority and request age are always included.

Include Clinical Service Request Type
Optional  ·  Default: On

Include the Clinical Service Request Type as a feature to train the prediction model. Priority and request age are always included.

Include Has Diagnostic Summary
Optional  ·  Default: On

Include a flag for whether the Clinical Service Request links to a Diagnostic Summary. Populates from the request's own lookup, so it adds signal even when Diagnostic Summary data is absent.

Include Has Patient Health Condition
Optional  ·  Default: On

Include a flag for whether the Clinical Service Request links to a Patient Health Condition. Populates from the request's own lookup, so it adds signal even when Patient Health Condition data is absent.

Include Diagnostic Summary Category
Optional  ·  Default: On

Include the Diagnostic Summary Category as a feature. Requires Diagnostic Summary data to be mapped; when absent the feature is simply empty and has no effect on the install.

Include Patient Health Condition Severity
Optional  ·  Default: On

Include the Patient Health Condition Severity as a feature. Requires Patient Health Condition data to be mapped; when absent the feature is simply empty and has no effect on the install.

Custom filters

The filter parameters are optional SQL expressions applied to the Clinical Service Request source. Leave them blank to score all Clinical Service Requests.

Custom Filter logic
Optional  ·  Default: (blank)

SQL filter applied to the Clinical Service Request source in both the training and scoring data transforms. Leave blank to score all Clinical Service Requests.

Custom Filter logic (Training)
Optional  ·  Default: (blank)

SQL filter applied only to the training data transform. Used together with a separate scoring filter.

Custom Filter logic (Scoring)
Optional  ·  Default: (blank)

SQL filter applied only to the scoring data transform. Used together with a separate training filter.

Target Variable

Defines the training label — the outcome the model learns to predict.

Target Variable details
Optional  ·  Default: referral acceptance (Binary, Maximize)

Defines the training label the model learns to predict. The condition is a SQL expression evaluated on the Clinical Service Request source and must return the numeric outcome value. Defaults to referral acceptance; override it for other Clinical Service Request use cases.

The default is made up of these sub-fields:

Sub-fieldDefaultMeaning
LabelDerived ScoreDisplay name of the predicted outcome.
FieldDerivedScore__cThe field that holds the derived training outcome.
TypeBinaryThe outcome is yes/no (accepted vs. not).
Success1Value that represents the positive outcome (accepted).
Failure0Value that represents the negative outcome (not accepted).
GoalMaximizeThe model optimizes for the success outcome.
ConditionThe SQL that computes the outcome (below).

The default condition classifies a request as accepted (1) when it is marked accepted or has reached an Active/Completed status:

CASE
  WHEN ssot__IsAccepted__c = 1 OR ssot__IsAccepted__c = true THEN 1
  WHEN ssot__ClinicalServiceRequestStatus__c IN ('Active', 'Completed') THEN 1
  ELSE 0
END
The label depends on IsAccepted being a real boolean The condition compares ssot__IsAccepted__c to true/1. This only matches if the data kit mapped acceptance into the DMO as a boolean (Step 1 does this). If acceptance arrives as text, the comparison never matches, every row gets label 0, and the model can hang in Activating. See Troubleshooting.

Parameters you don't set

Two parameters are managed by the framework — leave them at their defaults: Train and Deploy (defaults to on) and an internal test flag used only by functional tests.

Finish and verify

4

Complete the wizard. The template installs the model definition and data transforms, then begins training.

5

Confirm the model reaches Active status. A model that stays in Activating can mean the training label is all one value — see Troubleshooting.
