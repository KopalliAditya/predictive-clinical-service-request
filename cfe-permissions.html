Step 3 — Enable the Score Writeback

Configure Copy Field Enrichment to copy the model's score from Data Cloud back onto the Clinical Service Request, and grant the integration user the permissions the writeback needs.

Why this step exists

The model writes its score into a Data Cloud DMO (ClinicalServiceRequestScoringData). To make that score visible to referral coordinators, it has to come back to the CRM. Copy Field Enrichment (CFE) is the Data Cloud feature that copies a DMO field back onto a CRM object.

The writeback runs as a fixed Data Cloud integration user — not as you. That user needs specific Health Cloud permissions (Part B). If they're missing, the rest of the setup looks healthy but the score never appears on the CSR.

Part A — Create the Copy Field Enrichment

1

In Data Cloud Setup, create a new Copy Field Enrichment.

2

Set the source object to Clinical Service Request Scoring Data (the scoring DMO the model writes to).

3

Set the target object to Clinical Service Request, and map the score to the Referral Score field.

Match on the record identifier Map the record identifier as the match key so each scoring row updates the right Clinical Service Request. The identifier flows from the CRM record through the DMO to the scoring DMO.
4

Save and start the enrichment.

Part B — Grant the integration user the required permissions

The writeback executes as the Data Cloud Customer 360 Data Platform Integration user (the cloud@<org> integration user), using the sfdc_a360 permission set. For the writeback to update a Health Cloud object, two things must be true:

  1. The Manage Health Cloud permission must be enabled on the sfdc_a360 permission set.
  2. The Health Cloud Platform permission set license must be assigned to the cloud@ integration user.

Option 1 — Setup UI

1

In Setup, open Permission Sets and select Customer 360 Data Platform Integration (API name sfdc_a360).

2

Under System Permissions, enable Manage Health Cloud and save.

3

In Setup, open Users, find the Customer 360 Data Platform integration user (login cloud@<your-org-id>), and assign the Health Cloud Platform permission set license.

Option 2 — Anonymous Apex

The same two grants in one script. Run from the Developer Console or sf apex run. The script looks the integration user up by its login prefix, so there are no org-specific IDs to paste in:

// Enable Manage Health Cloud on the Data Cloud integration permission set
PermissionSet a360 = [SELECT Id FROM PermissionSet WHERE Name = 'sfdc_a360' LIMIT 1];
a360.PermissionsManageHealthCloud = true;
update a360;
System.debug('Enabled ManageHealthCloud on sfdc_a360');

// Assign the Health Cloud Platform PSL to the cloud@ integration user
User cloudUser = [SELECT Id FROM User WHERE Username LIKE 'cloud@%' AND IsActive = true LIMIT 1];
PermissionSetLicense psl = [SELECT Id FROM PermissionSetLicense
                            WHERE DeveloperName = 'HealthCloudPlatformPsl' LIMIT 1];
if (0 == [SELECT COUNT() FROM PermissionSetLicenseAssign
          WHERE AssigneeId = :cloudUser.Id AND PermissionSetLicenseId = :psl.Id]) {
    insert new PermissionSetLicenseAssign(
        AssigneeId = cloudUser.Id, PermissionSetLicenseId = psl.Id);
    System.debug('Assigned HealthCloudPlatformPsl to ' + cloudUser.Id);
}
Restart the sync after changing permissions Permission changes don't apply to an enrichment that's already running. After granting the permissions, do a full Stop then Start of the data sync / enrichment so the writeback picks up the new access.

How to verify the writeback works

1

Confirm the Referral Score field exists on Clinical Service Request. If it doesn't, the CFE target mapping was never created — go back to Part A. You can check with a field query:

SELECT QualifiedApiName FROM FieldDefinition
WHERE EntityDefinition.QualifiedApiName = 'ClinicalServiceRequest'
  AND QualifiedApiName LIKE '%Referral%'
2

Confirm scores are landing. After a sync run, count CSR records with a non-null score, using the field API name returned by the query above:

SELECT COUNT(Id) FROM ClinicalServiceRequest WHERE ReferralScore != null

A non-zero, growing count means the writeback is working end to end.

3

Confirm coordinators can see it. Open a scored Clinical Service Request as a referral coordinator and verify the Referral Score field is on the page layout and visible to their profile.

Done When the score count is non-zero and growing, and coordinators can see the Referral Score on the record, the feature is fully set up. New Clinical Service Requests will be scored on each sync cycle.
