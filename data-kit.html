Step 1 — Install the Health Cloud Scoring Data Kit

Deploy the data kit that maps your Clinical Service Request data into the Data Cloud model objects the scoring model reads.

Why you need this

The scoring model doesn't read your CRM directly — it reads Data Model Objects (DMOs) in Data Cloud. The data kit defines the data streams that bring ClinicalServiceRequest and its related objects from the CRM into those DMOs.

Without the data kit, the DMOs the model expects are missing or empty, and Step 2 fails its readiness checks.

About the "CSRScore" stream bundle Inside the Health Cloud Scoring data kit, the bundle of data streams is named CSRScore. You'll see this name on the Data Streams page after deployment — it's the group of streams this kit creates, not a separate thing to install.

What the data kit contains

The Health Cloud Scoring data kit (CSRScore bundle) creates four data streams, each mapping a source object to a DMO:

Source objectTarget DMO
Clinical Service RequestClinicalServiceRequestDmo
Clinical Service Request DetailClinicalServiceRequestDetailDmo
Diagnostic SummaryDiagnosticSummaryDmo
Health ConditionPatientHealthConditionDmo

Diagnostic Summary and Health Condition supply the optional model features (Diagnostic Summary Category and Patient Health Condition Severity). If you don't map that data, those features are simply empty — see Step 2.

The acceptance field is mapped for you The Clinical Service Request stream includes a formula field that converts the request's IsAccepted value into the IsAccepted field on the DMO. The default training label reads that field. If acceptance looks unmapped after deploy, see Troubleshooting: model stuck in Activating.

Deploy the data kit

1

From Setup, go to Data Cloud Setup and select Data Kits.

2

Select Health Cloud Scoring.

3

Review the contents, then click Data Kit Deploy.

4

Select the data space you want to deploy into, and enter your org ID.

5

Click Deploy.

6

Wait for the deployment to finish. Track its progress on the Deployment History tab.

Verify the DMO field mappings

After deployment, confirm the field mappings landed correctly:

7

From the App Launcher, open Data Streams.

8

Confirm each of the four streams is mapped to its DMO. On the Clinical Service Request stream, confirm the fields the model relies on are mapped: Priority, Status Start Date, and Accepted (IsAccepted).

Confirm data is flowing before Step 2 Mapping the streams isn't enough — the DMOs must contain rows. After the streams run, confirm the ClinicalServiceRequest DMO has at least 400 records (see Prerequisites). An empty DMO fails Step 2's readiness check.
