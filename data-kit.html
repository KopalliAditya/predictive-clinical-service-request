Step 1 — Install the Health Cloud Scoring Data Kit

Deploy the data kit that maps your Clinical Service Request data into the Data Cloud model objects the scoring model reads.

Why you need this

The scoring model doesn't read your CRM directly — it reads Data Model Objects (DMOs) in Data Cloud. The data kit is what connects the two. It defines the data streams that pull ClinicalServiceRequest and its related objects out of the CRM and map them, field by field, into the DMOs.

Without the data kit, the DMOs the model expects are either missing or empty, and Step 2 will fail its readiness checks.

About the "CSRScore" stream bundle Inside the Health Cloud Scoring data kit, the bundle of data streams is named CSRScore (short for Clinical Service Request Score). You'll see this name on the Data Streams page after deployment — it's the group of streams this kit creates, not a separate thing to install.

What the data kit contains

The Health Cloud Scoring data kit (CSRScore bundle) creates four data streams, each mapping a source object to a DMO:

Source objectTarget DMOWhat it provides
Clinical Service RequestClinicalServiceRequestDmoThe record being scored: priority, status, status start date, and the acceptance outcome used as the training label.
Clinical Service Request DetailClinicalServiceRequestDetailDmoDetail-level reference data linked to the request.
Diagnostic SummaryDiagnosticSummaryDmoDiagnostic category — an optional model feature.
Health ConditionPatientHealthConditionDmoPatient health condition severity — an optional model feature.
The acceptance field is mapped for you The CSR stream includes a formula field that converts the request's IsAccepted value into the boolean IsAccepted field on the DMO. This matters because the training label reads that boolean. If acceptance looks unmapped after deploy, see Troubleshooting: model stuck in Activating.

Deploy the data kit

1

From Setup, go to Data Cloud Setup and select Data Kits.

2

Select Health Cloud Scoring.

3

Review the contents, then click Data Kit Deploy.

4

Select the data space you want to deploy into, and enter your org ID.

5

Click Deploy.

6

Wait for the deployment to finish. Track its progress on the Deployment History tab.

Verify the DMO field mappings

After deployment, confirm the field mappings landed correctly:

7

From the App Launcher, open Data Streams.

8

Open each stream from the CSRScore bundle and confirm these mappings exist:

Data streamFields mapped to the DMO
Clinical Service RequestPriority, Status, Status Start Date, and Accepted (IsAccepted)
Clinical Service Request DetailDetail record reference
Diagnostic SummaryDiagnostic Category
Patient Health ConditionSeverity
Confirm data is flowing before Step 2 Mapping the streams isn't enough — the DMOs must actually contain rows. After the streams run, confirm the ClinicalServiceRequest DMO has at least 400 records (see Prerequisites). An empty DMO is the number-one reason Step 2's readiness check fails.
